# 项目章程

## 项目信息

**项目名称：** 消费电子产品售后维修与产品追溯管理系统

**项目类型：** 五人数据库课程设计

**项目目标：** 实现一个可运行、可查询、可修改数据库数据的 Web 系统，完成需求分析、总 ER 图、模块 ER 图、关系表、主外键和完整性定义，并在五分钟内演示一条完整业务链。

**完成标准：** 五个人均有可审核的设计、代码、测试和讲解内容；系统在 2026 年 10 月 23 日前达到可演示状态；组长在 2026 年 11 月 1 日前提交报告。

## 项目范围

系统围绕两条业务链展开。

### 售后主流程

```text
产品 SN 与保修查询
→ 客户提交售后申请
→ 客服受理并生成 RMA
→ 维修人员检测产品
→ 登记故障与维修结果
→ 换新或结案
```

### 产品追查

```text
零件批次
→ 生产批次
→ 产品 SN
→ 售后故障
```

产品追查只实现支持答辩演示的一条链，不延伸为完整生产系统。

## 范围之外

本项目不开发以下内容：

- 供应商采购和付款
- 完整仓储和盘点
- 真实物流接口
- 财务退款和支付
- 生产排程与车间执行
- 完整客户关系管理
- 用户注册、找回密码、短信和邮件
- 复杂数据迁移和历史数据兼容
- 移动端应用

## 技术方案

```text
浏览器：HTML + CSS + 原生 JavaScript + Bootstrap
数据请求：Fetch API
服务端：Java + Spring Boot
数据访问：MyBatis-Plus
数据库：MySQL 8
项目管理：Maven
协作：GitHub Issues + Fork + Pull Request
```

页面 JavaScript 只能调用 Spring Boot API，不能直接连接 MySQL。

MyBatis-Plus 用于普通单表操作；跨表查询、产品追查和统计查询使用 Mapper XML 或手写 SQL。项目保留 Controller、Service、Mapper 三层。

## 数据库约定

数据库只维护当前可用版本，不保存每一次结构变化。

```text
sql/
├── schema.sql
└── demo-data.sql
```

- `schema.sql` 保存当前完整表结构，由 A 检查并维护。
- `demo-data.sql` 保存演示数据，可以随时覆盖。
- 表结构调整后，成员清空本地数据库并导入当前 SQL 文件。
- 业务密码写入个人本地配置，不提交仓库。
- 仓库提交 `application-local.example.yml`，个人使用的 `application-local.yml` 加入 `.gitignore`。

## 团队原则

- C、D、E 负责本模块的表设计和模块 ER 图。
- A 检查命名、主外键、字段类型、完整性和跨模块关系，并合并总 ER 图。
- 每位模块负责人都要参与后端、页面和测试。
- A、B 主要处理公共设计、审查、接口约定和联调，减少批量 CRUD。
- B、C、D、E 各自 Fork A 的公开仓库，在个人 Fork 中创建分支、提交代码并向上游仓库发起 PR。
- A 负责仓库规则、PR 审核意见和最终合并。
- 成员没有上游仓库写入权限，只有 A 执行最终合并。
- PR 合并时使用 merge commit，保留 no-ff 的分支历史。
- 出现延期时先缩减次要内容；A 只接管影响核心演示链的问题。

## 成功条件

项目同时满足以下条件才算完成：

1. 能从统一 SQL 文件初始化 MySQL 数据库。
2. 页面能通过 Spring Boot API 查询和修改数据库数据。
3. 三个角色具有不同操作范围。
4. 核心业务状态不能随意跳转。
5. 总 ER 图和模块 ER 图与最终表结构一致。
6. 五位成员均有独立 PR、测试证据和答辩内容。
7. 五分钟演示能够完整走通预定业务链。
