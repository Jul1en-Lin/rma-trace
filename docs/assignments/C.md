# C 任务书

## 角色

产品型号、生产批次、产品实例和保修查询模块负责人。

## 表设计

负责三张表的字段初稿和模块 ER 图：

- `product_model`：产品型号及默认保修月数
- `production_batch`：一个型号的一次生产批次
- `product_instance`：通过唯一 SN 识别的具体产品

固定关系为：

```text
product_model 1 ── N production_batch
production_batch 1 ── N product_instance
```

提交给 A 检查的内容包括字段、类型、非空规则、唯一约束和外键。

## 功能责任

- 实现三张表的新增、查询和修改，不实现删除。
- 实现产品数据管理与 SN 查询页面。
- 实现按 SN 查询型号、批次、销售日期和保修状态。
- 保修规则为“销售日期 <= 当天 < 销售日期 + 型号保修月数”。
- 编写至少一条手写保修业务查询。

## 不负责

- 不增加独立保修政策、零件批次和生产用料关系表。
- 不实现售后申请、RMA、检测和维修逻辑。
- 不自行决定跨模块外键。

## 验收

- 型号编号、生产批次编号和 SN 的唯一约束有效。
- 有效 SN 可以查到型号、批次、销售日期和保修状态。
- 不存在的 SN 返回明确提示。
- 页面刷新后数据仍来自 MySQL，不使用前端写死数据。
- 至少提交测试证据和独立 PR，并能解释三张表的关系。

## 依赖

- A 检查表设计以及产品实例与售后申请的跨模块关系。
- B 提供公共后端结构和统一响应格式。
