# C 任务书

## 角色

产品型号、产品 SN 和保修查询模块负责人。

## 负责范围

- 设计产品与保修模块的表和分 ER 图。
- 编写字段说明、主外键和业务约束。
- 实现产品型号与产品实例的 Controller、Service、Mapper。
- 实现 SN 和保修查询 API。
- 实现产品与保修查询页面。
- 编写至少一条手写保修业务查询。
- 完成本模块接口测试和页面测试。

## 不负责

- 不修改售后申请、RMA 和维修模块内部逻辑。
- 不自行决定跨模块外键，先提交给 A 检查。
- 不直接向上游 `main` 推送代码。

## 交付

- 产品与保修模块 ER 图
- 字段和业务规则说明
- 产品与保修后端代码
- 产品与保修页面
- 手写 SQL、测试结果和页面截图
- 关联 Issue 的 PR

## 验收

- 输入有效 SN 可以查到产品型号和保修信息。
- 输入不存在的 SN 得到明确提示。
- SN 唯一约束有效。
- 页面数据来自 MySQL，不使用前端写死数据。
- 能在答辩中解释本模块表关系和查询流程。

## 依赖与求助

- A 检查模块表设计和跨模块关系。
- B 提供公共后端结构和统一响应格式。
- Spring Boot 或 Git 问题先在 Issue 记录，再 @A 或 @B。
