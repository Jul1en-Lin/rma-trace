# B 任务书

## 角色

公共后端、登录权限、RMA 状态和后端代码审查。

## 表设计

负责两张表的字段初稿和模块 ER 图：

- `app_user`：系统登录账号和固定角色
- `rma_order`：受理后生成的正式处理单

提交给 A 检查的内容包括字段、类型、非空规则、唯一约束、外键和状态取值。

## 功能责任

- 准备 Spring Boot、MySQL 和 MyBatis-Plus 公共项目结构。
- 提供统一接口响应、异常格式和事务示例。
- 实现固定演示账号登录及三个角色的服务端检查。
- 提供从已受理申请创建 RMA 的 Service 方法。
- 实现 RMA 查询、状态检查和结案。
- 为 E 提供检测、维修状态推进的调用方式。
- 与 E 共同完成 RMA、检测与维修处理页面。

## 不负责

- 不实现动态角色配置、状态回退、换新或操作日志。
- 不代替 C、D、E 完成各自表和后端。
- 不执行上游仓库的最终合并。

## 验收

- 用户名唯一，三个演示角色的操作范围不同。
- 一份售后申请最多生成一张 RMA。
- RMA 只能按“待检测 → 待维修 → 待结案 → 已结案”推进。
- 非法状态操作返回明确原因。
- 已结案 RMA 不能继续写入检测或维修数据。
- 至少提交一条手写业务 SQL、测试证据和独立 PR。

## 依赖

- A 确认实体关系骨架和数据库约定。
- D 调用 B 提供的方法创建 RMA。
- E 调用 B 提供的状态检查和推进方法。
