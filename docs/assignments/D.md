# D 任务书

## 角色

客户、售后申请和客服受理模块负责人。

## 负责范围

- 设计客户与售后申请模块的表和分 ER 图。
- 编写字段说明、主外键和申请状态规则。
- 实现客户与售后申请的 Controller、Service、Mapper。
- 实现申请创建、查询、受理和拒绝接口。
- 实现客户与售后申请页面。
- 编写至少一条客户历史申请查询。
- 完成本模块接口测试和页面测试。

## 不负责

- 不实现 RMA 后续状态、检测和维修逻辑。
- 不自行决定跨模块外键，先提交给 A 检查。
- 不直接向上游 `main` 推送代码。

## 交付

- 客户与售后申请模块 ER 图
- 字段和业务规则说明
- 客户与售后申请后端代码
- 客户与售后申请页面
- 手写 SQL、测试结果和页面截图
- 关联 Issue 的 PR

## 验收

- 可以为存在的客户与产品创建售后申请。
- 申请可以受理或拒绝，处理完成后不能再次操作。
- 受理后能调用 B 的流程生成 RMA。
- 页面数据来自 MySQL，不使用前端写死数据。
- 能在答辩中解释申请和 RMA 的区别。

## 依赖与求助

- A 检查模块表设计和客户、产品关系。
- B 提供 RMA 创建入口和统一响应格式。
- C 提供可以查询的产品 SN。
