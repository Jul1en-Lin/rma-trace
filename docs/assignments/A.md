# A 任务书

## 角色

项目负责人、数据库总设计、界面规范、仓库维护和最终集成。

## 负责范围

- 确认需求边界和主演示链。
- 检查 C、D、E 提交的模块表设计。
- 统一表名、字段名、字段类型、主外键和完整性。
- 合并总 ER 图并维护当前 `schema.sql`。
- 设计页面布局和交互规范。
- 实现产品 SN 追查接口、页面和多表 SQL。
- 管理 GitHub Issues、审核 PR、执行最终合并。
- 组织联调、五分钟演示和报告整理。

## 不负责

- 不代替 C、D、E 完成模块表初稿。
- 不承担全组所有 Controller、Service 和 Mapper。
- 不接管不影响主演示链的次要功能。

## 交付

- 项目章程与 MVP Spec
- 总 ER 图
- 数据库规范和完整 SQL 快照
- 产品追查功能
- 页面规范
- PR 审核记录与发布版本
- PPT、演示脚本和备用视频

## 验收

- 总 ER 图与当前表结构一致。
- 所有模块能通过统一 SQL 初始化。
- 输入 SN 能查询生产批次、零件批次和售后故障。
- 所有合并 PR 具有审核记录。
- 10 月 23 日主演示链可以完整执行。

## 协作

- 表结构与 ER 图问题由 A 决定最终方案。
- 公共后端与 RMA 状态问题和 B 共同检查。
- A 处理 C、D 的设计审查，并和 B 一起照看 E。
