# A 任务书

## 角色

项目负责人、数据库关系检查、产品追查、仓库维护和最终集成。

## 数据库责任

- 主持九张表的实体关系骨架评审。
- 检查 B、C、D、E 提交的字段、主外键、唯一约束和状态取值。
- 合并总 ER 图、字段说明、`schema.sql` 和 `demo-data.sql`。
- 检查演示数据能否贯穿申请、RMA、检测、维修和结案。
- 不额外负责业务表首稿，不替代模块负责人补字段。

## 功能责任

- 实现按产品 SN 查询型号、生产批次和售后处理结果的手写多表 SQL。
- 实现产品追查 API 和页面。
- 制定五个页面的公共布局和最少交互约定。
- 管理 Issues、审核 PR、执行最终合并并组织联调。

## 交付

- 总 ER 图和数据库检查记录
- 当前完整 SQL 快照与演示数据
- 产品追查功能及测试证据
- 页面约定、集成版本、演示脚本和贡献汇总

## 验收

- 九张表可以由统一 SQL 创建并导入演示数据。
- 总 ER 图、字段说明和实际表结构一致。
- 输入 SN 能查询型号、生产批次、申请、故障判断和维修结果。
- 每个合并 PR 只包含相关文件并具有审核证据。
- 主演示链可以完整运行。

## 协作边界

- A 决定跨模块关系的最终方案，但不直接覆盖成员尚未讨论的字段设计。
- 公共后端和 RMA 状态问题与 B 一起检查。
- 进度受阻时先删选做内容，再处理影响数据库和主演示链的问题。
